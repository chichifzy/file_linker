# 文件浏览（file_linker）

在电脑上运行一个服务，同一局域网内的手机、平板、其他电脑用浏览器就能浏览这台电脑上共享的文件（只读）。

- 支持预览纯文本（txt、md、代码等，大文件只显示前 1MB）、图片和视频（支持拖动进度）。
- 其他类型的文件只显示名称、大小、修改时间，服务端不会读取它们的内容。
- 支持按文件名搜索、显示/隐藏以 `.` 开头的隐藏文件。

## 启动

需要先安装 [Go](https://go.dev/dl/)、[Node.js](https://nodejs.org/) 20+ 和 pnpm（`npm install -g pnpm`）。

| 系统 | 构建并启动 | 只构建可执行文件 |
| --- | --- | --- |
| macOS | 双击 `start.command`，或终端运行 `./start.sh` | `./start.sh build` |
| Linux | `./start.sh` | `./start.sh build` |
| Windows | 双击 `start.bat` | `start.bat build` |

首次启动会提示创建管理员账号。启动后命令行窗口会列出访问地址：

```text
服务已启动，按 Ctrl+C 停止。
  本机访问:   http://localhost:8080
  局域网访问: http://192.168.1.23:8080
```

只构建时生成 `bin/file_linker`（Windows 为 `bin\file_linker.exe`），前端已打包在里面，可以单独复制到别处运行。数据库默认是当前目录下的 `data.db`。

常用参数：

```text
file_linker -addr :8081                      换端口
file_linker -db /path/to/data.db             指定数据库位置
file_linker -cache-gb 20                     限制转码缓存上限（默认 0，不限制）
file_linker create-admin <用户ID> <用户名>    创建管理员（只能有一个）
```

## 使用

1. 管理员在**运行服务的这台电脑上**打开 `http://localhost:8080` 登录，在“共享目录”中添加要共享的文件夹。其他设备上登录管理员账号看不到这个入口。
2. 管理员在“邀请码”中生成邀请码，发给其他人。每个邀请码只能注册一个普通用户。
3. 点击左下角头像 →“分享二维码”，其他设备扫码即可打开页面，用邀请码注册后浏览文件。

## 视频编码转换

部分视频（AV1、HEVC 等）手机浏览器无法解码。这类视频播放失败时，页面会显示它的实际编码，并给出「转换编码」按钮，点击后由运行服务的电脑用 ffmpeg 转成 H.264。

- 转码过程中边转边播：播放器此时拿到的是 HLS 播放列表，按“直播”处理，时长还在增长，不能往前拖。
- 转码完成后自动切换成普通 mp4 并从当前进度接着播，此时可以自由拖动进度条。
- 最终只保留一个 mp4 成品（分段与播放列表在完成约 1 分钟后清理），缓存在系统缓存目录（Windows 为 `%LOCALAPPDATA%\file_linker\media`），**默认不限制容量、永久保留**，重启服务后仍然有效，同一个视频再次打开直接播放。
- 只有在左侧「转码缓存」页面手动删除时才释放空间。想限制占用可在启动时指定上限，超出后按最久未使用淘汰：`file_linker -cache-gb 20`
- 转码可选依赖 [ffmpeg](https://ffmpeg.org/download.html)。Windows 上 `start.bat` 会询问是否自动安装；缺少它不影响浏览和下载，只影响这个功能。

## 视频缩略图

文件列表里的视频缩略图由服务端用 ffmpeg 抽一帧生成，缓存在 `%LOCALAPPDATA%\file_linker\thumbnails`（约 10~40 KB/个，第二次进入目录直接命中）。

早期版本是在列表里直接放 `<video preload="metadata">` 让浏览器自己取首帧，一个目录里有几十个大视频时，这些元素会各自占用一个连接去读文件头，把浏览器对单个域名的 6 个连接占满，点开视频的请求只能排队——表现就是“目录里视频越多，点开越慢”。换成小图后单个请求几毫秒结束，连接不再被占住。

没装 ffmpeg 时会退回用 `<video>` 取首帧，但同一时刻最多只有 3 个在途，不会再把连接占满。

播放时如果还在加载/缓冲，画面中央会显示当前的下载速度（如 `缓冲中 · 12.6 MB/s`）和已缓冲比例；速度由「已缓冲时长 ÷ 总时长 × 文件大小」估算，HLS 边转边播时没有确定的总大小，只显示缓冲比例。

服务端对每个「拉了 20MB 以上或耗时 3 秒以上」的视频请求会在控制台打一行摘要，例如：

```
INFO media file=xxx.mp4 range="bytes=0-" status=206 bytes=26.0MB duration=312ms ua=iPhone/Safari
```

服务端本身是流式的（支持 Range，不会等整段读完再发）。如果某个请求的 `bytes` 接近整个文件大小，说明是播放器在整段下载——常见原因是 MP4 的索引（`moov`）在文件尾，移动端播放器只能读到末尾才能开始解析。这种片子可以用 `ffmpeg -i in.mp4 -c copy -movflags +faststart out.mp4` 无损重封装一次。

## 安全说明

- 只有登录用户能访问文件，只能访问共享目录内的文件，指向共享目录以外的符号链接会被忽略。
- 服务使用 HTTP，适合在家庭或办公室等可信局域网中使用，不要直接暴露到公网。
- 首次运行时，系统防火墙可能询问是否允许接收网络连接，需要允许，否则其他设备无法访问。

## 开发

```bash
make dev      # 同时启动后端和前端开发服务器，访问 http://localhost:5173
make build    # 生产构建，输出 bin/file_linker
```
