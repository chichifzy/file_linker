# 文件浏览（file_linker）

在电脑上运行一个服务，同一局域网内的手机、平板、其他电脑用浏览器就能浏览这台电脑上共享的文件（普通用户只读）。

- 支持预览纯文本（txt、md、代码等，大文件只显示前 1MB）、图片和视频（支持拖动进度）。
- 其他类型的文件只显示名称、大小、修改时间，服务端不会读取它们的内容。
- 支持按文件名搜索、显示/隐藏以 `.` 开头的隐藏文件。
- 管理员在文件浏览页右上角的「+」里可以**新建文件夹**、**按链接下载文件**到当前目录（见下文），下载任务在侧边栏的「任务列表」里随时可查。
- `.zip` / `.7z` 压缩包有自己的图标，管理员可以把它**解压到当前目录**（有密码的也能解，见下文）。

## 启动

需要先安装 [Go](https://go.dev/dl/)、[Node.js](https://nodejs.org/) 20+ 和 pnpm（`npm install -g pnpm`）。

| 系统 | 构建并启动 | 只构建可执行文件 |
| --- | --- | --- |
| macOS | 双击 `start.command`，或终端运行 `./start.sh` | `./start.sh build` |
| Linux | `./start.sh` | `./start.sh build` |
| Windows | 双击 `start.bat` | `start.bat build` |

首次启动会提示创建管理员账号。启动后命令行窗口会列出访问地址：

```text
服务已启动，按 Ctrl+C 停止。
  本机访问:   http://localhost:8080
  局域网访问: http://192.168.1.23:8080
```

只构建时生成 `bin/file_linker`（Windows 为 `bin\file_linker.exe`），前端已打包在里面，可以单独复制到别处运行。数据库默认是当前目录下的 `data.db`。

常用参数：

```text
file_linker -addr :8081                      换端口
file_linker -db /path/to/data.db             指定数据库位置
file_linker -cache-gb 20                     限制转码缓存上限（默认 0，不限制）
file_linker -cache-dir D:\video-cache         指定转码缓存目录（网页上改过则以网页设置为准）
file_linker create-admin <用户ID> <用户名>    创建管理员（只能有一个）
```

## 使用

1. 管理员在**运行服务的这台电脑上**打开 `http://localhost:8080` 登录，在“共享目录”中添加要共享的文件夹。其他设备上登录管理员账号看不到这个入口。
2. 管理员在“邀请码”中生成邀请码，发给其他人。每个邀请码只能注册一个普通用户。
3. 点击左下角头像 →“分享二维码”，其他设备扫码即可打开页面，用邀请码注册后浏览文件。

## 新建文件夹与按链接下载

文件浏览页右上角（面包屑右侧）有一个「+」按钮，只有管理员能看到，两项操作都作用于**当前所在目录**：

- **新建文件夹**：输入名称后在该目录下创建一个文件夹。名称不能包含 `/`、`\`，不能以点结尾（Windows 不允许），也会挡掉 `CON`、`NUL` 这类保留名；同名时提示已存在。
- **下载文件**：粘贴 `http://` 或 `https://` 链接，由运行服务的这台电脑去下载，文件直接落到当前目录。
  - 文件名依次取「响应头 `Content-Disposition` → 链接路径 → 按 `Content-Type` 推断扩展名」；重名时自动加 ` (1)`、` (2)`。
  - 先写隐藏的临时文件 `.file_linker-dl-*`，完整下完才改名，中途取消或失败不会留下半个文件。
  - 弹窗里显示进度、已下载大小和速度；点「后台继续」（或按 Esc、点遮罩）即可关掉弹窗，下载会在服务器上继续跑完。
  - 侧边栏的**任务列表**列出所有下载任务：正在下载的能看进度和速度，已完成的可以「打开目录」，失败或取消的可以「重试」，都能「移除」记录；侧边栏名称旁的红色数字是正在下载的任务数。
  - 任务记录保存在数据库（`downloads` 表）里，**只有你主动移除或清除才会消失**；服务重启时没下完的任务会标成「已中断」，可以重试。
  - 取消会删除临时文件，已经下完的文件不受影响。
  - 同时最多 2 个下载任务，超出会提示稍后再试；没有整体超时（大文件要下很久），但连接、TLS 握手、等待响应头都有上限。
  - 支持跳转（最多 10 次），也可以从局域网内的 NAS 等地址下载；服务器返回非 200 时直接报错，不会把错误页当成文件存下来。

写入接口在后端用 `requireAdmin` 保护（`POST /api/fs/mkdir`、`POST /api/fs/download`、`POST /api/fs/rename`、`POST /api/fs/delete`、`POST /api/fs/paste`、`POST /api/fs/extract`），普通用户调用会返回 403。若想让所有登录用户都能写，把 `internal/server/server.go` 里这些接口的 `s.requireAdmin(...)` 换成 `s.requireUser(...)`，前端把 `<Toolbar canWrite>` 和 `<Listing canWrite>` 改成 `true` 即可——但这等于让受邀的访客可以往你的磁盘里写东西、删你的文件，不建议在共享给多人时打开。

## 重命名与删除

每个文件 / 文件夹一行的最右边有个「⋯」按钮（只有管理员能看到），点开是「重命名」和「删除」。

- **重命名**：输入框里是完整文件名，默认只选中主文件名（不含扩展名），直接打字就替换名字、后缀保留。**扩展名可以随便改**，`a.txt` 改成 `b.zip` 也行。只能改名、不能借此移动位置；重名会提示「已存在同名文件或文件夹」，`a.txt → A.txt` 这种只改大小写的可以。名称校验与新建文件夹一致（不含 `/`、`\`，不以点结尾，避开 `CON`、`NUL` 等保留名）。
- **删除**：弹窗二次确认后**移到系统回收站**，不是直接抹掉，需要时能还原：
  - Windows：进**回收站**（和资源管理器按 Delete 一样，右键可以「还原」）。
  - macOS：进**废纸篓**，可以在废纸篓里右键「放回原处」；外接磁盘上的文件按 macOS 约定放进该卷的 `.Trashes/<uid>`。
  - Linux：按 freedesktop 规范进 `~/.local/share/Trash`（带 `.trashinfo`，桌面环境的回收站里能看到）。
  - 系统回收站用不了的情况（跨卷、没有桌面会话、回收站被禁用等），退回共享目录里的隐藏目录 `.file_linker-trash/<日期>/<原路径>`，页面上会明确提示去了哪里。文件只是被移走，不会丢。
  - 回收站里的东西不会再出现在网页的列表里（`.file_linker-trash` 是隐藏目录，勾选「显示隐藏文件」能看到）。想彻底删除就去系统回收站里清空。
  - `.file_linker-trash` 目录本身不能在网页上再删除。

## 拷贝、剪切与粘贴

文件行「⋯」里还有「拷贝」和「剪切」（仅管理员），点了只是记住这一项，不会立刻动磁盘。

- 进入目标文件夹后，面包屑右侧会出现「粘贴」按钮，按钮上带着记住的名字，点一下就复制或移动过来。切换到别的页签再回来，记忆还在；刷新页面则清空。
- **拷贝可以连续粘到多个文件夹**；**剪切粘贴成功后就忘掉**，粘贴按钮随之消失。跨共享目录也能粘。
- 粘贴按钮右边的小箭头展开后点「取消选择」，清除记忆，粘贴按钮一起消失；这只取消选择，不会动文件。
- 目标位置已有同名项时，先弹窗问你：选「取消」只取消**这一次**粘贴，记住的文件（夹）还在，按钮也不会消失；选「继续粘贴」才保存成 `xxx (1)`、`xxx (2)`，绝不覆盖已有文件。
- 剪切优先用同盘重命名（瞬间完成），跨盘退回复制后删除；复制会保留原来的修改时间，文件夹里的符号链接会被跳过。
- 文件夹不能粘进它自己（或它的子目录）里，根目录本身也不能被拷贝或剪切。

## 解压压缩包

支持 `.zip` 和 `.7z`。有「解压」两个入口，都只对管理员显示：文件行右边的「⋯」里选「解压」，或者点开压缩包后在弹窗里点「解压到当前文件夹」。

- 解压到**压缩包所在的目录**，不做覆盖：同名文件自动加 ` (1)`、` (2)`。
- 支持密码：zip 的 ZipCrypto 与 AES-128/192/256、7z 的 AES-256 都能解。没有密码时直接开始；需要密码会就地弹出输入框，输错了提示「密码不正确」并留在弹窗里重输，不用重新发起任务。
- 先在目标目录里建一个隐藏临时目录 `.file_linker-ex-<任务号>`，全部解完才合并成正式文件，中途取消或失败不会留下半拉子文件；服务异常退出遗留的临时目录会在下次解压时自动清掉。
- 弹窗里显示进度、速度和解压出的文件数；**关闭弹窗会取消这次解压**并清掉临时内容（已经合并进去的文件不受影响）。
- 压缩包里的符号链接会被跳过，条目名里带 `..`、绝对路径或盘符的也会被丢弃，防止解出到共享目录外面；跳过多少条会在完成时提示。
- 同时最多 2 个解压任务，超出会提示稍后再试。
- 解压是纯 Go 实现（`internal/unpack`），不需要另装 7-Zip、unzip 或任何命令行工具。
- 压缩包不能在网页里直接预览（当文本读出来是乱码），点开是一个说明页加「解压到当前文件夹」按钮。

## 视频编码转换

部分视频（AV1、HEVC 等）手机浏览器无法解码。这类视频播放失败时，页面会显示它的实际编码，并给出「转换编码」按钮，点击后由运行服务的电脑用 ffmpeg 转成 H.264。

如果只是**容器不对**（例如把 `.mkv` 改名成 `.mp4`，或者直接用 `.mkv` / `.avi` / `.flv` 文件），而视频是 H.264、音频是 AAC/MP3，那么不需要重新编码，只换封装就够了：点击后立刻开始转换，1.2GB 的片子几秒完成，画质无损。这种文件在列表里直接点开就会自动开始，不需要先点按钮。

- 转码过程中边转边播：播放器此时拿到的是 HLS 播放列表，按“直播”处理，时长还在增长，不能往前拖。
- 转码完成后自动切换成普通 mp4 并从当前进度接着播，此时可以自由拖动进度条。
- 最终只保留一个 mp4 成品（分段与播放列表在完成约 1 分钟后清理），缓存在系统缓存目录（Windows 为 `%LOCALAPPDATA%\file_linker\media`），**默认不限制容量、永久保留**，重启服务后仍然有效，同一个视频再次打开直接播放。
- 打开视频时先查一次缓存：命中就直接播转码好的 mp4，不会再去请求原文件、也不会闪一下「需要转码」的提示。缓存目录换过、服务重启过都照样认得（缓存按「路径 + 大小 + 修改时间」记录，跟目录位置无关）。
- 只有在左侧「转码缓存」页面手动删除时才释放空间。想限制占用可在启动时指定上限，超出后按最久未使用淘汰：`file_linker -cache-gb 20`
- 缓存目录可以在「转码缓存」页面上直接改（管理员可见）：换到空间更大的磁盘时，填一个新目录保存即可，已有的缓存会自动迁移过去、原目录随后清空，不用重新转换。也可以一次指定：`file_linker -cache-dir D:\video-cache`（命令行优先于网页设置）。迁移要求目标目录为空、且没有正在转换的视频；跨盘迁移是复制后删除，几个 GB 需要一点时间，期间请勿关闭服务。
- 转码可选依赖 [ffmpeg](https://ffmpeg.org/download.html)。Windows 上 `start.bat` 会询问是否自动安装；缺少它不影响浏览和下载，只影响这个功能。

## 视频缩略图

文件列表里的视频缩略图由服务端用 ffmpeg 抽一帧生成，缓存在 `%LOCALAPPDATA%\file_linker\thumbnails`（约 10~40 KB/个，第二次进入目录直接命中）。

早期版本是在列表里直接放 `<video preload="metadata">` 让浏览器自己取首帧，一个目录里有几十个大视频时，这些元素会各自占用一个连接去读文件头，把浏览器对单个域名的 6 个连接占满，点开视频的请求只能排队——表现就是“目录里视频越多，点开越慢”。换成小图后单个请求几毫秒结束，连接不再被占住。

没装 ffmpeg 时会退回用 `<video>` 取首帧，但同一时刻最多只有 3 个在途，不会再把连接占满。

播放时如果还在加载/缓冲，画面中央会显示当前的下载速度（如 `缓冲中 · 12.6 MB/s`）和已缓冲比例；速度由「已缓冲时长 ÷ 总时长 × 文件大小」估算，HLS 边转边播时没有确定的总大小，只显示缓冲比例。

服务端对每个「拉了 20MB 以上或耗时 3 秒以上」的视频请求会在控制台打一行摘要，例如：

```
INFO media file=xxx.mp4 range="bytes=0-" status=206 bytes=26.0MB duration=312ms ua=iPhone/Safari
```

服务端本身是流式的（支持 Range，不会等整段读完再发）。如果某个请求的 `bytes` 接近整个文件大小，说明是播放器在整段下载。

## 扩展名不可信：按文件头判断容器

有些文件扩展名是 `.mp4`，实际是 Matroska(MKV) 封装。服务端原来按扩展名给 `Content-Type: video/mp4`，iOS Safari 拿它当 MP4 解析，永远解析不出索引，于是退化成不带 Range 的整段下载——1.2GB 的片子要下三十多秒才报错。

现在输出视频前会先读 64 字节文件头判断真实容器（`ftyp` → mp4/mov、`1A45DFA3` → Matroska/WebM、`RIFF....AVI ` → AVI、`FLV` → FLV、`0x47` → MPEG-TS）：

- 浏览器装不下的容器（mkv / avi / flv / ts / ps）直接返回 `415`，响应带 `X-Container`，浏览器立刻报错而不是白下几个 GB；
- 前端拿到 `415` 后调用 `/api/fs/codec`，服务端用 ffmpeg 读出真实容器、视频编码、音频编码与时长，返回 `{container, codec, audio, duration, playable, remuxable}`；
- `playable=false && remuxable=true` 时前端自动开始转换（走上面的无损封装），否则显示「转换编码」按钮。

`.mkv` / `.avi` / `.flv` / `.wmv` / `.mpg` / `.mpeg` / `.m2ts` 也被当作视频列出，点开同样是这条路径。

## 索引在文件尾的 MP4（虚拟 faststart）

很多下载来的 MP4 把索引（`moov`）放在文件末尾。这类文件 iOS Safari 打开时经常直接发一个不带 Range 的 GET，必须读完整个文件才能解析索引，表现就是「文件越大等越久，1GB 基本打不开」。

服务端遇到这种文件时不会去复制一份，而是在内存里把 `moov` 挪到流的最前面，并修正它内部记录的 chunk 偏移（整段顺序移动，所有偏移的增量相同），再用虚拟的 ReadSeeker 交给 `ServeContent`：

- 客户端拿到的仍是一个结构完全合法的 MP4，`Content-Length` 与原文件一致，Range / 拖动进度条照常工作
- 磁盘占用为零，开播即时（索引在前，播放器读几百 KB 就能开始）
- 只处理「单个 mdat、非分片、moov 在 mdat 之后」的普通 MP4；其他结构原样输出
- 下载链接始终给原文件，保证下载回来的字节与磁盘上完全一致
- 这类响应会带一个 `X-Faststart: virtual` 响应头，便于确认是否走了虚拟视图

解析结果（头部 + 修正后的 moov）按「路径 + 大小 + 修改时间」缓存在内存里，最多 24 个文件 / 64MB，避免每个 Range 请求都重新读一遍索引。

## 安全说明

- 只有登录用户能访问文件，只能访问共享目录内的文件，指向共享目录以外的符号链接会被忽略。
- 新建文件夹、按链接下载、重命名、删除、拷贝/剪切/粘贴、解压只允许管理员操作（普通用户 403）。下载链接是由服务器去请求的，拿到管理员账号就相当于能以这台电脑的身份访问内网地址，请只给自己使用。
- 解压不会写出共享目录之外：条目路径会逐段清洗，`..`、绝对路径、符号链接一律跳过。
- 重命名和删除不会跟随符号链接：操作的是链接本身，不会顺着链接改到共享目录外面去。
- 服务使用 HTTP，适合在家庭或办公室等可信局域网中使用，不要直接暴露到公网。
- 首次运行时，系统防火墙可能询问是否允许接收网络连接，需要允许，否则其他设备无法访问。
